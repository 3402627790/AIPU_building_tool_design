# 2026-08-02

- 向用户讲解了项目技术栈（含分层架构图）：C++17 无异常编译器核心（libaipubuildtool.so，MC/MQ 双路径）+ Python 前端（AIPUBuilder CLI，pybind11 绑定 _C）+ AIPU MLIR dialect（aipugc，仅 x86_64 host）+ GOP 插件/预编译内核（OpenCL）+ AIPU LLVM 工具链/driver/simulator 生态。构建：CMake ≥3.14，-Wall -Werror，可选 OpenMP/gcov/静态标准库，支持 Linux x86_64 与 Android ARM 交叉编译。产物：AIPU ELF/.bin（MC·ZY ISA）与 Compass ELF（MQ）。
- 排查 cpscc：AIPU/Compass 工具链（compass-toolkit）的 C 编译器，用于把 `.cps` 动态形状/设备代码编译为 `.o`，由 src/builder/code_generator.cpp 在 gen_device_code 中调用（cpscc -dc -O2）。查找顺序：环境变量 CPSCC → PATH 中的 cpscc → Debug 版回退集群路径 /project/ai/scratch01/compass-toolkit/compiler/latest/bin/cpscc；--cps-path 取自 CPS_PATH（Debug 默认 /project/ai/scratch01/compass-toolkit/toolkit/latest）。本地直接敲 cpscc 找不到需 source env_setup.sh 或配 PATH/CPSCC/CPS_PATH。
- cpscc vs cpshostcc 区别：cpscc 是 Compass 工具链的**设备(device) C 编译器**，编译 `.cps` 设备代码→`.o`（给 AIPU 芯片跑），用 `--cps-path`/`-dc`/`-O2`，查 CPSCC→PATH→集群路径。cpshostcc 本质是 **g++**（默认，除非设 CPSHOSTCC），带 `-fPIC -shared -O2` 并链接 `libaipubtrt`/`libdl`，编译 `.cpp` host 端 wrapper（CPU 侧运行）。调用处发现接口不对称：code_generator.cpp:174 调 `cpshostcc(c_file, objs, o_file)`（3 参），但 toolchain.h/.cpp 仅定义 2 参 `cpshostcc(c_file, out)`，疑似演进遗留，需核实是否应把 host objs 一起链接。
- 确认对应关系（代码核实）：**aipuocc ↔ MC 路径**（AIPU/LLVM 后端，emitter + linker_v2 使用，`-target aipu -mcpu=`）；**cpscc ↔ MQ 路径**（Compass toolkit，code_generator.cpp 被 mqbuilder.cpp 实例化使用）。README.md:166 明确 code_generator.cpp 属 MQ 路径。故"aipuocc=MC compiler、cpscc=MQ compiler"的断言成立。aipuocc 本质是基于 LLVM/Clang 加 AIPU 后端的定制编译器（默认路径 toolchain/llvm/binary/bin/aipuocc），cpscc 是 Compass toolkit 独立提供的设备编译器。
